控制散佈包中的檔案¶

在最常見的使用案例中，setuptools 會自動找出發布套件所需的檔案。更精確地說，來源碼散佈包預設包含以下檔案：

  • 由 pyproject.toml 中的 py-modules 和 packages 設定參數，及/或 setup.cfg/setup.py 中對應參數所隱含的純 Python 模組檔案；

  • 在 setup() 的 ext_modules 或 libraries 引數中提到的 C 來源碼檔案；

  • 符合下列 glob 模式的檔案：tests/test*.py、test/test*.py；

  • 由 pyproject.toml 中的 scripts-files 設定參數或 setup.py/setup.cfg 中的 scripts 指定的腳本；

  • 由 pyproject.toml 中的 package-data 和 data-files 設定參數，及/或 setup.cfg/setup.py 中對應參數所指定的所有檔案；

  • 由 setup.cfg 中 license_file 選項指定的檔案；

  • 由 pyproject.toml 中的 license-files 設定參數，及/或 setup.cfg/setup.py 中對應參數所指定的所有檔案；請注意，如果你未明確設定此參數，setuptools 將包含任何符合下列 glob 模式的檔案：LICEN[CS]E*、COPYING*、NOTICE*、AUTHORS**；

  • pyproject.toml；

  • setup.cfg；

  • setup.py；

  • README、README.txt、README.rst 或 README.md；

  • MANIFEST.in

請注意，上述清單保證在最新穩定版的 setuptools 中運作。較舊版本的行為可能有所不同。

備註

在 v69.0.0 版被加入: setuptools 預設會嘗試在散佈包中包含型別資訊檔案（.pyi 和 py.typed，如 PEP 561 所述），只要這些檔案位於套件目錄內即可（目前還不支援自動處理頂層的 .pyi 檔案）。

但請注意，此功能為實驗性功能，未來可能有所變更。

如果你的專案中有 .pyi 和 py.typed 檔案，但不希望發布它們，你可以透過設定 exclude-package-data 來排除。

然而，在建置較複雜的套件時（例如包含非 Python 檔案的套件，或需要使用自訂 C 標頭檔的套件），你可能會發現專案資料夾中的檔案並非全部都會包含在套件的 發行封存檔 中。

如果你使用的是 版本控制系統，例如 git 或 mercurial，且你的來源碼散佈包只需要包含你在版本控制中追蹤的檔案，你可以使用 setuptools 的 外掛程式，例如 setuptools-scm 或 setuptools-svn，來自動將所有受追蹤的檔案納入 sdist。

或者，如果你需要對檔案進行更精細的控制（例如你不想發布與 CI/CD 相關的檔案），或者你需要自動產生的檔案，你可以在專案根目錄中加入 MANIFEST.in 檔案，來指定預設檔案定位演算法未捕捉到的任何檔案。

此檔案包含指示，告訴 setuptools 哪些檔案應該（或不應該）是 sdist 的一部分。

注意

請注意，setuptools 支援的是 MANIFEST.in，而不是 ``MANIFEST``（無副檔名）。任何建議使用 ``MANIFEST``（無副檔名）的文件、教學或範例很可能都已過時。

小訣竅

MANIFEST.in 檔案包含允許你探索和操作檔案清單的指令。有許多指令可用於不同的目的，但你應盡量不要讓 MANIFEST.in 檔案過於細碎。

一個好做法是從 graft 指令開始（加入一組目錄內的所有檔案），然後透過移除多餘的檔案或加入個別檔案來微調檔案選取。

MANIFEST.in 檔案由指令組成，每行一個指令，指示 setuptools 從 sdist 中加入或移除某些檔案。這些指令如下：

指令

說明

include pat1 pat2 ...

加入符合任何列出之模式的所有檔案（必須以相對於專案根目錄的路徑指定檔案）

exclude pat1 pat2 ...

移除符合任何列出之模式的所有檔案（必須以相對於專案根目錄的路徑指定檔案）

recursive-include dir-pattern pat1 pat2 ...

加入符合 dir-pattern 的目錄下、且符合任何列出之模式的所有檔案

recursive-exclude dir-pattern pat1 pat2 ...

移除符合 dir-pattern 的目錄下、且符合任何列出之模式的所有檔案

global-include pat1 pat2 ...

加入來源碼樹中任何位置符合任何列出之模式的所有檔案

global-exclude pat1 pat2 ...

移除來源碼樹中任何位置符合任何列出之模式的所有檔案

graft dir-pattern

加入符合 dir-pattern 的目錄下的所有檔案

prune dir-pattern

移除符合 dir-pattern 的目錄下的所有檔案

這裡的模式是 glob 樣式模式：* 符合零個或多個一般檔名字元（在 Unix 上，除正斜線外的所有字元；在 Windows 上，除反斜線和冒號外的所有字元）；? 符合單個一般檔名字元；而 [chars] 符合方括號內的任何一個字元（可包含字元範圍，例如 [a-z] 或 [a-fA-F0-9]）。Setuptools 也支援 **，可符合包含正斜線、反斜線和冒號在內的零個或多個字元。

目錄模式是相對於專案目錄的根目錄；例如，graft example* 會包含專案根目錄中名為 examples 的目錄，但不會包含 docs/examples/。

MANIFEST.in 中的檔案和目錄名稱應以 / 分隔；setuptools 會自動將斜線轉換為當地平台適用的目錄分隔符號。

指令會按照它們在 MANIFEST.in 檔案中出現的順序處理。例如，給定以下指令：

graft tests
global-exclude *.py[cod]

目錄樹 tests 的內容會先被加入 sdist，然後 sdist 中所有副檔名為 .pyc、.pyo 或 .pyd 的檔案會從 sdist 中移除。如果指令順序相反，則 *.pyc 等檔案只會從加入 tests 之前的 sdist 中移除；如果 tests 恰好包含任何 *.pyc 檔案，它們最終會包含在 sdist 中，因為排除是在它們被加入之前發生的。

以下是按照 src-layout 組織的簡單專案之 MANIFEST.in 範例：

# MANIFEST.in -- 僅供說明
graft src
graft tests
graft docs
# `-> 加入目錄內的所有檔案

include tox.ini
# `-> 比對相對於專案根目錄的檔案路徑

global-exclude *~ *.py[cod] *.so
# `-> 比對檔案名稱（無論目錄為何）

一旦正確的檔案存在於 sdist 中，它們就可以在建置過程中被二進位擴充功能使用，或者如果你將 setuptools 設定為 include_package_data=True，則會包含在最終的 wheel [1] 中。

重要

請注意，使用 include_package_data=True 時，預設情況下最終的 wheel 中只會包含軟體包目錄內的檔案。

例如，如果你建立一個使用 setuptools-scm 的 Python 專案，且在套件資料夾外有一個 tests 目錄，那麼 tests 目錄會存在於 sdist 中，但不會存在於 wheel [2] 中。

更多資訊請參閱 Data Files Support。

快取與疑難排解¶

Setuptools 會自動建立一些目錄來存放建置產物和快取檔案，例如 build、dist、*.egg-info。雖然快取有助於加速增量建置，但在某些邊緣情況下可能會變得過時。如果你覺得快取導致建置出現問題，特別是在變更設定或目錄/檔案結構後，請考慮在重新建置或重新安裝專案之前移除 build、dist、*.egg-info [3]。

[1]

你可以將建置過程視為兩個階段：首先會建立 sdist，然後從該 sdist 產生 wheel。

[2]

這是因為 sdist 可以包含在開發或建置過程中有用、但在執行時期不需要的檔案（例如測試、文件、範例等）。另一方面，wheel 是一種已經過最佳化的檔案格式，準備好解壓縮到正在執行中的 Python 安裝或 虛擬環境 中。因此它只包含執行時期所需的項目。

[3]

當從解壓縮的 sdist 工作時（例如進行修補），你也可以考慮移除 PKG-INFO 檔案以強制重新建立。
